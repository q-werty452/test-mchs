# Туруктуу Жалалабад — прототип

Интерактивный прототип государственной системы управления рисками ЧС
для Джалал-Абадской области КР по ТЗ `02_TZ_Turuktuu_Jalalabad_Pilot_MVP.docx`.

**Все данные в прототипе вымышленные.** В шапке приложения постоянно висит
плашка «ДЕМО-ДАННЫЕ · НЕ ДЛЯ ОПЕРАТИВНОГО ИСПОЛЬЗОВАНИЯ» — показ не должен
допускать прочтения выдуманных цифр как настоящих.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5180
npm run build    # производственная сборка в dist/
```

## Структура

```
src/
  types/          доменная модель по разделам 4–9 ТЗ
  data/           демонстрационные данные, по файлу на модуль
  api/client.ts   фасад доступа к данным — единственная точка замены на backend
  state/app.tsx   текущая роль, полномочия, уведомления интерфейса, загрузка данных
  map/            MapLibre: подложка, слои, геометрия, маркеры
  screens/        экраны разделов
  ui/             компоненты, иконки, графики, форматирование
  theme/          токены оформления и глобальные стили
```

## Замена демо-данных на рабочий backend

Компоненты не импортируют `src/data` напрямую — только `api` из `src/api/client.ts`.
Там же лежит изменяемое состояние стенда и имитация задержек сети.

Для перехода на Django REST меняется только этот файл: тела методов заменяются
на `fetch('/api/v1/...')`, сигнатуры сохраняются. Например:

```ts
async getZones(): Promise<RiskZone[]> {
  const res = await fetch('/api/v1/zones/');
  if (!res.ok) throw new Error(`Ошибка загрузки зон: ${res.status}`);
  return res.json();
}
```

Проверки полномочий в `client.ts` (`setZoneLevel`, `createEvent`,
`approveNotification` и др.) воспроизводят логику, которая в рабочей системе
обязана выполняться на стороне backend. При переходе они заменяются на
обработку ответов `403` — клиентская проверка остаётся только для блокировки
недоступных действий в интерфейсе.

Геометрия зон и границ районов упрощена и является демонстрационной. При
загрузке официальных GIS-данных заменяется содержимое `src/data/territories.ts`
и `src/data/zones.ts`; код карты не меняется.

## Что демонстрирует прототип

Сквозной сценарий из таблицы 6.3 ТЗ, проходимый кликами:

1. Метеостанция МС-04 «Кёк-Арт» — осадки за 12 ч 40,0 мм при пороге 30 мм,
   влагонасыщение 88 % при пороге 72 % (`/weather`).
2. Детерминированный движок правил фиксирует срабатывание R-MUD-02 без участия
   языковой модели и показывает расчёт по каждой станции (`/rules`).
3. Оператор открывает событие ЧС по зоне риска (`/events` → «Создать событие»).
4. Событие ведётся: план действий, ответственные, сроки, хронология (`/events/:id`).
5. Формируется черновик уведомления по утверждённому шаблону.
6. Уполномоченный сотрудник подтверждает отправку — без подтверждения доставка
   невозможна (`/notifications`).
7. Журнал доставки заполняется статусами по каналам, включая ошибки SMS.
8. AI-помощник даёт сводку с источниками и уровнем уверенности, действий не
   выполняет; при низкой уверенности передаёт решение сотруднику (`/ai`).
9. Каждый шаг попадает в журнал аудита со старым и новым значением (`/audit`).

Переключатель роли в шапке меняет видимые территории и доступные действия:
районный сотрудник не может изменить зону чужого района, аким и население не
видят служебные силы и средства МЧС.

## Известные ограничения

- Карте нужен интернет для тёмной подложки CARTO. При отсутствии сети выводится
  предупреждение, подложка не загружается, но зоны, объекты и все экраны
  продолжают работать.
- Изменения (созданные события, уведомления, записи аудита) хранятся в памяти
  вкладки и сбрасываются при перезагрузке страницы.
